# Releases

## Current publication status

As of 2026-09-23, the repository has no Git tags and the GitHub Releases page has no published releases. Files under [`docs/releases/`](releases/) are draft release-note material, not published releases. They should not be treated as a version history or evidence that a deployment was made.

There is no `CHANGELOG.md`: without published versions, a changelog would suggest a release history that does not exist. For current changes, use the commit history. When a release is ready, create and review its tag and GitHub release together, then update this page.

## Draft notes

The existing files `v0.1.0.md` through `v0.5.0.md` record a proposed historical narrative for the academic project. They may be used as source material for a future release only after their target commits, contents, and version order are checked. They do not imply that those tags or releases currently exist.

## Publishing a future release

1. Confirm the application and documentation are ready for users.
2. Identify the exact commit to release and choose a version.
3. Review the release notes against that commit; state the checks that were actually run.
4. Create the annotated Git tag and GitHub release from the selected commit.
5. Verify the published release page and tag after publishing.
