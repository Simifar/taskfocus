## Логотипы

`src/shared/ui/brand-logo.tsx` использует исходные SVG без изменений. Класс `.dark`
существующего ThemeProvider переключает primary/inverse через CSS, включая первый
рендер. Горизонтальные версии используются в авторизации, мобильной шапке задач
и шапке профиля/настроек; символ 32 px — в боковой панели рядом с существующим
названием. Горизонтальные изображения имеют ширину 180, 152 и 132 px соответственно,
что превышает минимальные 120 px. Изображения масштабируются пропорционально;
добавлено свободное поле, отсутствуют декоративные фоны, тени и фильтры.

Удалены старый анимированный знак T и Brain как идентификатор приложения. README
на обоих языках используют `<picture>` со светлой/тёмной версией. `/logo.svg`
сохранён для совместимости и содержит точную копию нового primary-символа;
внутри приложения этот путь больше не используется. Существующие скриншоты в
`docs/images/` сохранены как исторические изображения, а не перерисованы.

презентационные PNG, splash и Android/iOS/Windows native exports остались в

иконки имеют квадратные непрозрачные фоны; дополнительное скругление не добавлено.

## Палитра и темы

Фирменные токены добавлены в `src/app/globals.css`. Для существующего `--brand`
на светлом фоне используется `#3156CA`, для тёмной темы — `#85A4FF`. Яркий
`#5278F6` сохранён в SVG и отдельном токене, а не назначен мелкому тексту.
Фирменная панель авторизации использует navy `#172C62` / tile `#1C326A` и
обратный текст `#F2F5FF`. Нейтральные поверхности, семантические цвета, шрифты
интерфейса и схема ThemeProvider сохранены. Контуры букв SVG не требуют Inter.
Заголовку панели задан явный `text-auth-panel-foreground`: общее правило `h2`
иначе перекрывало наследование и делало текст тёмным на navy в светлой теме.

## Metadata, manifest и PWA

`src/app/layout.tsx` подключает manifest, SVG/ICO/PNG favicon, Apple touch icon,
applicationName, appleWebApp, Open Graph и Twitter `summary_large_image` через
Next.js Metadata API. `Viewport.themeColor` задаёт `#F3F6FF` для светлого и
`#172C62` для тёмного системного предпочтения. Эти media-запросы следуют настройке
ОС; переключатель темы приложения управляет UI независимо от них.

Абсолютный URL OG/Twitter строится через `metadataBase`: `NEXT_PUBLIC_SITE_URL`,
затем `NEXTAUTH_URL`, затем HTTPS `VERCEL_URL`, затем `http://localhost:3000`.
В production задайте публичный origin в `NEXT_PUBLIC_SITE_URL` или существующем
`NEXTAUTH_URL`; локальный fallback предназначен для разработки. Пример добавлен
только в `.env.example`; реальные `.env*` и облачные настройки не менялись.
Заголовок и описание сохраняют существующие фактические формулировки продукта.

Манифест расположен в корне: `id`, `start_url` и `scope` равны `./`, относительные
пути `icons/` разрешаются от `/manifest.webmanifest`. Обычные и maskable-иконки
имеют отдельные `purpose`. Для размещения под подпутём нужно согласованно изменить
пути Metadata, SVG и манифеста. Service worker/offline-режим не добавлялись:
набор иконок и манифест сами по себе не подтверждают offline/PWA-установку.

## Проверка

После последнего изменения:

- `npm run check` — PASS: ESLint без предупреждений, TypeScript, 54/54 теста.
- `npm run build` — PASS: Prisma Client generation, Next.js production build,
  18/18 страниц. Использован временный `DATABASE_URL` только в процессе сборки;
  это проверка генерации/компиляции, а не подключения или миграции базы данных.
- Побайтовое сравнение production-ассетов с Brand Kit — PASS. Совпадают четыре
  SVG, все 11 файлов `icons/`, manifest и OG-карточка; compatibility SVG и корневой
  ICO совпадают с соответствующими новыми файлами.
- Все 19 URL ассетов на локальной standalone production-сборке возвращают HTTP 200.
  В отрендеренном `<head>` проверены manifest, favicon, Apple touch icon,
  абсолютные OG/Twitter image URL, размеры 1200×630 и оба theme-color.
- PNG PWA 192/512 и Apple 180×180 непрозрачны. Фирменные пиксели maskable-иконок
  укладываются в круг 80%: максимальный радиус от центра составляет 0.366 и 0.368
  стороны соответственно, при допустимом 0.4. ICO содержит 16/24/32/48/64/128/256.
- Во встроенном браузере регистрация проверена при 320, 390, 768 и 1440 px в
  светлой и тёмной теме; вход — на desktop и при 390 px в обеих темах. Загружается
  соответствующий primary/inverse SVG, горизонтального переполнения нет.
- `DashboardSidebar`, `AccountShell` и `BrandLogo` дополнительно отрендерены
  в изолированном локальном стенде с production CSS и синтетическим пользователем:
  обе темы при 320/390/768/1440 px, ширины горизонтальных SVG 132/152/180 px,
  отдельный знак 32 px и квадратный favicon при 16/24/32/48 px — PASS.
  Стенд не добавлен в приложение или `public/`.
- После исправления заголовок панели в светлой теме имеет `rgb(242, 245, 255)`
  на `rgb(23, 44, 98)`. В проверенных страницах нет console warnings/errors.
  Временные настройки темы и размера браузера восстановлены; тестовые вкладки закрыты.
